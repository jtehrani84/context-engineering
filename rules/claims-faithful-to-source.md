# Claims Faithful to Source (P0 — the third sibling of the proof family)

`proof-before-claim.md` stops a stale GREEN. `findings-are-perishable.md` stops a stale RED. This rule stops the third failure: a **confident assertion that contradicts or outruns the source it rests on** — most dangerously in the *convenient* direction, and most expensively in a customer-, support-, or leadership-facing artifact.

## Why this is an AI-dev problem specifically

When one agent researches, drafts, AND finalizes an artifact, no second reader ever crosses a claim against its source. The agent holds the grounding (a doc excerpt, a query result) in the same context where it writes the prose — so a subtle inversion or overclaim reads back as confidently true, because it was generated by the same confident process now re-reading it. The relying human sees a polished, cited document and has no independent way to tell "faithfully sourced" from "plausibly worded." Both look authoritative.

Worked example of the failure mode: a support handoff stated a change "leaves the existing integration untouched," when the retrieved release note said the change "can break" exactly that integration. The fact had a reassuring face and a cautionary face; the comfortable one got written. The source was in hand — it was misread, not unknown.

## The rule

**Before an external-facing artifact is "ready to send," every factual and causal claim in it must be re-verified against its source — not re-read in your own prose, re-read in the source. Tag each claim DOCUMENTED (source says it), INFERRED (you reason it; the source doesn't state it), or UNSUPPORTED (neither — cut it or find a source). A chain with one inferred link is a hypothesis, labeled as such — never "documented."**

| Evidence: "is this claim true?" | Trust |
|----------|-------|
| It reads cleanly in my draft | **none** — fluency is not faithfulness |
| I remember the source said this | **claim** — memory inverts, especially toward convenience |
| I paraphrased it a moment ago | **claim** — the paraphrase is where inversion happens |
| **I just re-read the source span and it states this** | **proof** (documented) |
| I re-read the source; it states the *premises* and I'm joining them | **inference** — label it, don't promote it |

## The five tells (how this fails in practice)

1. **The reassuring caveat.** When a caveat *comforts* ("no impact," "leaves X untouched," "safe"), re-read the source — comfort is the signature of an unverified inversion.
2. **"Documented" over a multi-step chain.** Check every link individually. Some-links-real ≠ chain-documented.
3. **Circular evidence.** The thing you're explaining cannot also be your proof.
4. **Unhedged absolutes** in external copy ("the fix," "never," "always," "only," "guaranteed"). Each needs a source span or gets softened.
5. **Scope creep on a term.** Using a named feature beyond what the doc scopes it to. Re-read the definition.

## Bound once (the signal-density counter-force)

Every faithfulness pass tends to ADD a caveat and never remove one. Run it a few times and one true bound gets restated 5–8× across defensive boxes — which a senior reader reads as insecurity, not rigor. Each bound lives in ONE canonical place; everywhere else state it already-bounded and brief, or point to the canonical bound. Faithfulness is a property of the claim, not of how many times you say it.

## Register-aware

In a vision/seller artifact, directional claims are the register working as intended — flag one only when it's dressed as measured/proven data (a stat or % with no source). In a technical artifact, bound every factual and causal claim. The line that holds in both: **never present a vision claim as a measured fact.**
